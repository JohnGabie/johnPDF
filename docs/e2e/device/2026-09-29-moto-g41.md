## Resumo

Todos os cenários aplicáveis passaram. Nenhum crash, ANR, FATAL ou OutOfMemory
no logcat durante toda a sessão (arquivo de crash buffer vazio). Nenhum problema
visual encontrado com font_scale 1.3. Um item adicional pedido pelo controller
(duplo-back físico a partir do leitor) também passou.

## Problemas visuais em font_scale 1.3

Nenhum problema encontrado. Especificamente verificado:
- "Página N de 200" não sobrepõe "🔓 Gira sozinha" (quebra de linha absorve o texto extra).
- Rótulos das abas inferiores (Recentes / Todos os PDFs) não cortam.
- Botões "Anterior"/"Próxima" mantêm o texto legível e centralizado.
- A barra de navegação do sistema neste aparelho usa os 3 botões clássicos (sem texto), portanto não é afetada por font_scale.

## Observações gerais (não são bugs, apenas notas)

- A pasta `johnPDF-teste` era a única fonte de PDFs visível na lista "Todos os PDFs" durante o teste — nenhum outro arquivo pessoal do usuário foi listado ou fotografado.
- O estado de bloqueio de rotação ("Gira sozinha" / "Travada") persiste entre a abertura de diferentes arquivos dentro da mesma sessão do app, em vez de reiniciar por arquivo. Não é uma falha funcional, mas pode valer a pena confirmar se esse é o comportamento pretendido.

## Limpeza realizada

- `/sdcard/Download/johnPDF-teste/` removida do dispositivo.
- Rescan de mídia disparado (`content call --method scan_volume`).
- `font_scale` restaurado para `1.0` (valor original).
- `accelerometer_rotation` e `user_rotation` restaurados para `0` / `0` (valores originais lidos no início do teste).
- App johnPDF permanece **instalado** no aparelho (não foi desinstalado).
- Tela deixada na Home do sistema (HOME pressionado).
