# Modo escuro da interface — Plano de implementação

> **Para trabalhadores agênticos:** SUB-SKILL OBRIGATÓRIA: use
> `superpowers:subagent-driven-development` (recomendado) ou
> `superpowers:executing-plans` para implementar este plano tarefa a tarefa.
> Os passos usam caixas de seleção (`- [ ]`) para acompanhamento.

**Goal:** Fazer o *chrome* do johnPDF (barras, listas, busca, diálogos, estados vazios,
tela de permissão) seguir o modo escuro do sistema, mantendo as páginas do PDF brancas
nos dois modos e nenhum par texto/fundo abaixo de 4,5:1.

**Architecture:** `Theme.kt` passa a ter dois `ColorScheme` completos (`LightColors` e
`DarkColors`, mesmo seed índigo `#3558D4`) selecionados por `isSystemInDarkTheme()`, mais
um `JohnColors` (via `staticCompositionLocalOf`) para os papéis que o Material 3 não tem
(vão entre páginas, ícone de PDF). Todo `tonalElevation` sai e cada superfície declara sua
cor explícita de `surfaceContainer*`; o flash branco do arranque a frio some com
`res/values/colors.xml` + `res/values-night/colors.xml` e um tema de plataforma DayNight em
`res/values-v29/themes.xml`. A regra de contraste vira teste: `ContrastTest.kt` (JVM puro)
trava AA 4,5:1 em todos os pares, AAA 7:1 nos papéis principais, 3:1 em divisores e no
estado desabilitado.

**Tech Stack:** Kotlin 2.1.21, Jetpack Compose (BOM 2025.05.00), Material 3, Android
`minSdk` 24 / `targetSdk` 36, JUnit 4 + Robolectric 4.14.1, `compose-ui-test-junit4`.

**Spec:** `docs/superpowers/specs/2026-09-29-dark-mode-ui.md`

## Global Constraints

Valores copiados da spec. Valem para **todas** as tasks; os requisitos de cada task os
incluem implicitamente.

- **Texto ≥ 4,5:1** (WCAG 2.1 AA, critério 1.4.3) em **ambos** os esquemas, sem exceção.
- **Papéis principais de texto ≥ 7:1** (WCAG 2.1 AAA, critério 1.4.6): `onSurface`,
  `onBackground` e `onSurfaceVariant` sobre `surface`, `background` e os cinco níveis de
  `surfaceContainer*`. Medido: pior caso 7,14:1 (`onSurfaceVariant` sobre
  `surfaceContainerHighest`, escuro) e 7,25:1 (mesmo par, claro).
- **Elementos não textuais que carregam informação ≥ 3:1** (WCAG 2.1, critério 1.4.11):
  `outlineVariant` sobre **todos** os seis níveis de superfície.
- **Estado desabilitado ≥ 3:1** — regra do projeto, mais rígida que a WCAG (que isenta
  desabilitado). Alpha **0,60** no conteúdo e **0,12** no container, nunca o 0,38 do M3.
  Medido, rótulo contra o container **já composto**: **3,93:1 no claro / 4,46:1 no escuro**.
  (A spec §4.4 cita 4,29 / 5,41 porque mede o rótulo contra `surfaceContainer` puro, sem
  compor o container a 12% por cima. Os dois números cumprem a regra; o deste plano é o
  mais conservador e é o que o teste usa.)
- **Zero `tonalElevation`** em qualquer arquivo de `app/src/main/java`.
- **Zero literal `Color(0x…)`** fora de `app/src/main/java/com/johngabie/johnpdf/ui/theme/Theme.kt`.
- **A página do PDF é `Color.White` literal** (`PdfPageBackground`) nos dois modos. Nunca
  `colorScheme.surface`. O bitmap em `MuPdfEngine.kt:88` (`eraseColor(Color.WHITE)`) fica
  **inalterado**.
- **`minSdk = 24`**: nada pode depender de API ≥ 25 sem um qualificador de recurso
  (`values-v29/`) ou uma checagem de `Build.VERSION.SDK_INT`.
- **Seed único:** claro e escuro derivam do índigo `#3558D4`. Se a paleta mudar (pergunta
  G5 da spec), só os hex das famílias `primary`/`secondary`/`tertiary` mudam; estrutura e
  testes continuam válidos.
- **Sem cor dinâmica** (`dynamicDarkColorScheme` / `dynamicLightColorScheme`). Está fora de
  escopo por decisão da spec §1.
- **Sem alternador de tema dentro do app.** O gatilho é só `isSystemInDarkTheme()`.
- **Idioma da interface:** todo texto visível ao usuário em pt-BR, como o resto do app.

## Review Focus

Cinco classes de entrada que a spec implica mas que nenhum teste existente exercita, em
ordem de probabilidade de machucar alguém de verdade. Cada linha tem um teste atribuído a
uma task.

1. **`primary` usado como cor de texto sobre um container claro.** É o rótulo de
   `TextButton` ("Cancelar", "abc Usar letras") e o botão de ação do Snackbar. No claro,
   `primary #3558D4` sobre `surfaceContainerHighest #E4E1E9` dá **4,64:1** — passa AA por
   0,14. Qualquer mexida no seed derruba isso primeiro. O segundo mais apertado de todos é
   `onSurfaceVariant #C6C5D0` sobre `surfaceVariant #45464F` no escuro, **5,49:1** — que a
   tabela da spec §4.2 não lista (ela afirma 7,14:1 como pior caso do escuro; isso vale só
   para o subconjunto AAA). Esperado: ≥ 4,5:1 nos dois esquemas, em todos os 40 pares.
   → **Task 1** (`light_text_pairs_meet_wcag_aa` / `dark_text_pairs_meet_wcag_aa`, que
   incluem `primary` sobre cada container) e **Task 2** (`worst_case_is_documented`).

2. **`outlineVariant` sobre a superfície mais próxima dele.** O divisor da lista é o único
   separador entre um PDF e o seguinte, e o padrão do Material Theme Builder dá 1,62:1 no
   claro / 1,75:1 no escuro — invisível para o público idoso. O erro não aparece sobre
   `surface`, aparece sobre `surfaceContainerHighest`. Esperado: ≥ 3:1 sobre os **seis**
   níveis (`surface` + cinco `surfaceContainer*`) nos dois esquemas.
   → **Task 2** (`dividers_are_visible_on_every_surface_level`).

3. **"Anterior" desabilitado na página 1 e "Abrir" desabilitado com o campo de senha
   vazio.** O M3 pinta com `onSurface` a 38% de alpha, o que dá 2,32:1 no claro — o rótulo
   vira um fantasma. Com 0,60 sobre o container a 0,12 dá 3,93:1 no claro e 4,46:1 no
   escuro. Esperado: rótulo
   desabilitado ≥ 3:1 contra o próprio container, nos dois esquemas, **e** o `BigButton`
   desabilitado precisa de fato usar esse helper (não adianta o helper existir e ninguém
   chamar). → **Task 2** (`disabled_label_stays_readable`) e **Task 9**
   (`disabled_big_button_uses_readable_alpha`).

4. **A página branca no escuro sem moldura.** Se o vão entre páginas ficar num cinza médio
   (ou pior, seguir `surface`), duas páginas brancas encostadas viram uma mancha só e o
   usuário perde onde uma acaba. Esperado: no escuro, `PdfPageBackground` contra
   `JohnTheme.colors.pageGap` ≥ 3:1 (medido 19,25:1); no claro o vão intencionalmente quase
   some (1,23:1) e isso **não** pode ser "corrigido" por um teste simétrico.
   → **Task 3** (`page_gap_frames_the_white_page_in_dark`,
   `pdf_page_background_is_white_in_both_modes`).

5. **Ícones da barra de status depois de trocar `SystemBarStyle.light` por `auto`.** Isto
   desfaz o conserto F6 do ciclo anterior — só é seguro **porque** agora existe esquema
   escuro. Se o `auto` for aplicado sem o `darkColorScheme` no lugar (ou se o
   `values-night/` faltar), a regressão F6 volta: ícones escuros sobre fundo escuro, ou
   flash branco no arranque a frio. Esperado: o app monta e mostra a Home sem crash com o
   sistema em modo noturno, e a `MainActivity` não referencia mais `SystemBarStyle.light`.
   → **Task 6** (`home_renders_in_night_mode`, `edge_to_edge_uses_auto_not_light`) e
   **Task 5** (`night_window_background_matches_dark_surface`).

package com.johngabie.johnpdf.ui.theme

import androidx.compose.material3.ColorScheme
import androidx.compose.ui.graphics.Color
import org.junit.Assert.assertTrue
import org.junit.Test
import kotlin.math.pow

/** Luminância relativa, WCAG 2.1 (https://www.w3.org/TR/WCAG21/#dfn-relative-luminance). */
private fun luminance(c: Color): Double {
    fun ch(v: Float): Double {
        val s = v.toDouble()
        return if (s <= 0.03928) s / 12.92 else ((s + 0.055) / 1.055).pow(2.4)
    }
    return 0.2126 * ch(c.red) + 0.7152 * ch(c.green) + 0.0722 * ch(c.blue)
}

/**
 * Razão de contraste WCAG: 1,0 (cores iguais) a 21,0 (preto contra branco).
 * Mesma fórmula de `tools/contrast.py` — se uma mudar, a outra tem que mudar junto.
 */
internal fun contrast(a: Color, b: Color): Double {
    val la = luminance(a)
    val lb = luminance(b)
    return (maxOf(la, lb) + 0.05) / (minOf(la, lb) + 0.05)
}

/** Os cinco níveis de container mais `surface` e `background`, como pares (nome, cor). */
internal fun ColorScheme.surfaceLevels(): List<Pair<String, Color>> = listOf(
    "surface" to surface,
    "background" to background,
    "surfaceContainerLowest" to surfaceContainerLowest,
    "surfaceContainerLow" to surfaceContainerLow,
    "surfaceContainer" to surfaceContainer,
    "surfaceContainerHigh" to surfaceContainerHigh,
    "surfaceContainerHighest" to surfaceContainerHighest,
)

/**
 * Todo par texto/fundo que o app realmente produz: os pares `onX`/`X` do M3 mais tudo
 * que o johnPDF escreve por cima de um container (texto principal, texto secundário,
 * rótulo de TextButton em `primary` e mensagem de erro em `error`).
 */
internal fun ColorScheme.textPairs(): List<Triple<String, Color, Color>> = listOf(
    Triple("onPrimary/primary", onPrimary, primary),
    Triple("onSecondary/secondary", onSecondary, secondary),
    Triple("onTertiary/tertiary", onTertiary, tertiary),
    Triple("onError/error", onError, error),
    Triple("onBackground/background", onBackground, background),
    Triple("onSurface/surface", onSurface, surface),
    Triple("onSurfaceVariant/surfaceVariant", onSurfaceVariant, surfaceVariant),
    Triple("onPrimaryContainer/primaryContainer", onPrimaryContainer, primaryContainer),
    Triple("onSecondaryContainer/secondaryContainer", onSecondaryContainer, secondaryContainer),
    Triple("onTertiaryContainer/tertiaryContainer", onTertiaryContainer, tertiaryContainer),
    Triple("onErrorContainer/errorContainer", onErrorContainer, errorContainer),
    Triple("inverseOnSurface/inverseSurface", inverseOnSurface, inverseSurface),
) + surfaceLevels().flatMap { (bgName, bg) ->
    listOf(
        "onSurface" to onSurface,
        "onSurfaceVariant" to onSurfaceVariant,
        "primary" to primary,
        "error" to error,
    ).map { (fgName, fg) -> Triple("$fgName/$bgName", fg, bg) }
}

class ContrastTest {

    private fun assertText(schemeName: String, scheme: ColorScheme) {
        scheme.textPairs().forEach { (name, fg, bg) ->
            val r = contrast(fg, bg)
            assertTrue("[$schemeName] $name = %.2f:1, mínimo 4.5:1".format(r), r >= 4.5)
        }
    }

    @Test fun dark_text_pairs_meet_wcag_aa() = assertText("escuro", DarkSchemeForTest)
}

class NoStrayColorsTest {

    /** O working dir dos testes unitários é o módulo (`app/`); a raiz do repo é o fallback. */
    private val sourceRoot: File = listOf(File("src/main/java"), File("app/src/main/java"))
        .firstOrNull { it.isDirectory }
        ?: error("não achei src/main/java a partir de ${File(".").absolutePath}")

            }

            emptyList<String>(),

            "literais Color(0x…) só podem existir em ui/theme/Theme.kt (spec §7)",
            emptyList<String>(),
            offenders(Regex("""Color\(0x"""), skip = { it.name == "Theme.kt" }),
        )
    }

    @Test fun the_scan_actually_reads_sources() {
